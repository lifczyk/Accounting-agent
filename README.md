# Агент распознавания бухгалтерских документов — прототип

## Что уже работает

- Приём файлов из папки Google Drive (поллинг, без webhook)
- Классификация типа документа через OpenRouter (structured output)
- Извлечение полей для ТОРГ-12 с confidence по каждому полю
- Проверка на дубликат документа (нормализация номера + сравнение сумм/строк)
- Сохранение результата в SQLite — основа для таблицы проверки
- Перенос обработанного файла в папку "Обработано" в Drive

## Что НЕ реализовано (сознательно, как заглушка)

- **`onec_client.py`** — методы `find_document`, `find_counterparty`,
  `find_nomenclature`, `create_document` вызывают `NotImplementedError`.
  Это ожидаемый контракт, а не рабочий код: нужно получить от ИТ-специалиста,
  обслуживающего 1С, реальные пути HTTP-сервиса, формат авторизации и структуру
  ответа, затем переписать эти четыре метода.
- **Экстракторы для УПД, ТТН, Акта, Чека** — в `openrouter_client.py` реестр
  `EXTRACTORS` содержит только `torg12`. Документы других типов сейчас просто
  откладываются в очередь ручной разметки (`process_file` это не ломает, а
  логирует и пропускает). Следующий шаг — по образцу `torg12_schema.json`
  сделать схемы для остальных типов.
- **Таблица проверки (UI)** — сейчас данные лежат в SQLite,
  `store.list_records_for_review()` отдаёт список записей, ожидающих проверки.
  Нужно либо выгружать это в Google Sheets, либо собрать простой веб-интерфейс.
- **Многостраничные PDF** — `drive_intake.py` скачивает файл как есть; если
  придёт PDF с несколькими документами подряд, классификатор увидит это как
  один документ. Постраничную разбивку и классификацию по страницам нужно
  добавить отдельно, когда дойдёте до этого типа файлов на практике.

## Запуск

1. `pip install -r requirements.txt`
2. Скопировать `.env.example` в `.env`, заполнить `OPENROUTER_API_KEY` и
   Google Drive переменные.
3. Создать сервисный аккаунт Google, выдать ему доступ к папке Drive
   (расшарить папку на email сервисного аккаунта), положить JSON-ключ как
   `service_account.json`.
4. `python pipeline.py` — запустит бесконечный цикл поллинга.
   Для разового прогона (например, для теста на эталонном наборе) —
   `python -c "from pipeline import run_once; run_once()"`.

3. Сделать схемы извлечения для УПД, ТТН, Акта по аналогии с

4. Решить, как оператор будет видеть `store.list_records_for_review()` —
